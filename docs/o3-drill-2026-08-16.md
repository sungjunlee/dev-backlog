# O3 On-Track Drill — 2026-08-16

Issue: [#363](https://github.com/sungjunlee/dev-backlog/issues/363) (Option A: measured drill)

Privacy note: private consumer repositories appear under stable aliases
(`consumer-A` … `consumer-E`, mapping kept outside this public repo, applied
2026-08-16); public consumers keep their real names. Aliased mentions are not
linked.

Charter O3 predicate under test: *"A user can answer 'is this project still on
track?' in under 5 minutes against a stable per-project reference axis
(`spec/charter.md`)."*

## Method

Agent-run timed drill, one consumer repo at a time. Per repo: start timestamp →
read `spec/charter.md` objective statuses, active sprint files (`status:
active` + latest Progress tail), and last 3 git commits → form an on-track
verdict → end timestamp. Elapsed is wall-clock including analysis; tool calls
are user-visible command boundaries (shadow-protocol counting convention).

Population: 6 consumer repos with a `spec/charter.md` found in the local
workspace (excluding dev-backlog itself); 5 drilled, `consumer-D` not drilled
(same stack as consumer-B, cut at the 3–5 sample bound stated in #363).

Median elapsed 4.8 s; worst case 7.5 s. All drilled repos cleared the 5-minute
bar by two orders of magnitude.

## Findings

1. **The bar holds where the axis exists.** 4/5 repos were assessable and each
   verdict was formed in under 8 seconds of agent wall-clock. Even scaling
   generously for human reading speed (charter objectives + sprint tail +
   `git log -3` ≈ 1–2 minutes of human reading), the 5-minute bar holds with
   wide margin.
2. **The method's precondition is the predicate charter format.** consumer-C has
   a charter but not the O-predicate axis, so the O3 question is structurally
   unanswerable there. O3's denominator must therefore be *repos with a
   spec-charter-format axis*, not *repos with any charter file*.
3. **The drill has diagnostic value beyond the bar.** It surfaced consumer-B's
   stale-active m5 sprint — exactly the drift class O4/backlog-doctor exists
   for, visible cross-repo in seconds.
4. **Caveat.** This drill was agent-run, not human-run; O3 says "a user".
   Agent timing is a lower bound and the reading-scale extrapolation above is
   an estimate, not a measurement. A validated status should wait for the
   drill recurring organically (e.g., at reassess time) rather than one dated
   synthetic run.
