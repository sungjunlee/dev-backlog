# Project Context

## Architecture Decisions

- One declared task authority: `.dev-backlog/.tracker` is one line the session reads (absent = `github`; `backlog` for the Backlog.md CLI, `files` as its legacy spelling; `gitlab`), parsed by `readTaskAuthority` in `scripts/lib.js` and by a mirrored guard in `scripts/sprint-close.sh`. The rails are the SKILL.md Task Authority table; there is no adapter in code (charter rev 20 Non-Goal), so adding an authority is one table row plus one allow-list entry and needs a measured consumer (GitLab is the stated exception). Scripts never call `gh`/`backlog`/`glab` for task state; milestones, comments, PR links, and closing are calls the session makes, with exactly two scripted exceptions kept by `references/authority-contract.md`: `sprint-close.sh --close-milestone` (GitHub-only, closes the milestone before any local mutation) and `triage-apply --apply` (accepted triage actions behind a human gate).
- The Work rail is the authority's Read verb (`gh issue view N --json body,comments` by default): the newest `## Agent Brief` comment overrides the body, a `spec_ref:` line overrides both, and a failed read is fail-closed — never fall back to sprint text or a local copy.
- Plan refs are `#N` and nothing else. The one parser is `parseIssueRef` / `parsePlanCheckbox` in `scripts/lib.js`; `scripts/lib.sh` mirrors it as `RE_ISSUE_REF` for the shell rails.
- Active tracks partition by scope through the ONE `scopesOverlap()` in `scripts/lib.js` — never re-implement it. `component:` equality or explicit `scope:` globs decide; disjoint tracks coexist as a portfolio and overlap fails loud.
- Scripts own exactly four surfaces: the sprint-file contract, fail-loud shared-state guards (track overlap, unmoored `[~]`, `status: completed`), the `sprint-state` JSON recovery rail, and the `triage-apply` human gate. The keep test for any surface is (1) guards shared or irreversible state, (2) a deterministic check the model cannot cheaply redo, (3) a wire contract another tool consumes; failing all three means delete, not rewrite, and a reviewer defending a deleted doc must show the consumer reading it. Deletion stops at history: v1.0.0 is reserved and is not a cleanup cut, so completed sprint files stay.

## Conventions

- Commit the active sprint file to main when opening it; a sprint that is untracked or only on a working branch is invisible to delegate worktrees branched from main, which may then seed a duplicate active sprint.
- JSON read surfaces (`next.sh --json` / `status.sh --json` via `sprint-state.js`) and `backlog-doctor.js` are the machine path — extend them instead of adding a second markdown parser. With relay deprecated the JSON has no external consumer; it stays as the fresh-session recovery rail.
- SKILL.md is goal / rail / Done-when per mode: state a rule once, name the script that enforces it, keep hard constraints only for shared or irreversible state. Re-add prose only after a conformance run shows a repeated mistake, never for an anticipated risk. Eval prompts live in `tests/evals/`, never in SKILL.md — an in-file prompt section is a self-contaminating answer key.
- No `skills/` file may carry an unconditional required-read of a cross-repo `../spec-charter/references/` path; it dangles for adopters without craftkit and the smoke test enforces it. `references/spec-fallback.md` is consumption-side only (~1 page cap): it says how these skills BEHAVE when the spec axis is thin or absent and never authors spec semantics, which stays craftkit's job.
- Sprint spec fields are optional and unchecked: `sprint-init.js` never emits `objectives:` (hand-written when a charter exists) and writes `component:` only from `--component`, a free track-scope string with no `spec/` lookup; nothing lints `spec/`. O4 drift detection is the `backlog-triage` Alignment section.
- Every change lands via a PR reviewed by a model family other than the one that wrote it, iterating until LGTM; the cumulative diff gets one cross-family read at batch boundaries, which is cheaper than per-PR review and catches the contradictions repetition hides. Fresh-session conformance recipe and retention live in `docs/conformance/README.md`; `codex exec` outside a git repo needs `--skip-git-repo-check`, takes the prompt on stdin with `-`, writes the final answer via `-o`, and reports token counts on stderr. A repeated PARTIAL earns either one clause in SKILL.md or an eval-side Expected relaxation, never both.
- The `backlog-triage` report is written by the session, not by scripts, and is GitHub-only. Before deleting any other judgment script, repeat the shape that retired the last ones: fixture, A render, B session report, checker over close set / protection / exclusions / anchors.

## Known Gotchas

- `gh issue create` does not support `--json`; a `create --json … || create -b "fallback"` chain fails the first call at flag parsing and posts the fallback placeholder as the real issue body. Capture the URL from stdout instead.
- Triage relationship edges are advisory: a merged-PR-link mention is evidence, not a close, which still needs an Obsolete Candidate plus an accepted apply checkbox. Never propose closing an issue referenced in the active sprint's Plan or Running Context, however stale it looks.
- In-flight Plan pointer grammar (parsed by `sprint-state.js`): `→ PR #N (state)` at end of line, or `[branch:name]`. Any other shape reads as unmoored and fails the live smoke assertion.
- When a flag is deleted, reject it explicitly rather than ignore it — a silently ignored `--dry-run` turns a preview into a real write. The rejection test is a guard on irreversible state, not a rewrite of the retired surface.
- Two parsers of one file drift: the `sprint-close.sh` shell guard and `readTaskAuthority` had to be aligned on BOM, CRLF, dangling symlinks, and "absent vs unreadable", and the next batch became reliable only once `next.sh` / `status.sh` rendered through `sprint-state.js --format text`. Route any third reader through node.
- Never chain `gh pr merge` after a grep-filtered test run — capture `$?` from `node --test` and from the smoke test first (the smoke test is fully offline, so a failure there is a real regression, not a network flake). A backtick inside a JS template literal reached main for one commit this way.
- Measure suite totals with one stated glob (`tests/*.test.js tests/*/*.test.js`) and keep it across records; quote no script line counts here, since they go stale every wave and the repo-only helpers under `tests/tools/` sit outside the shipped bundle, so naming them by filename trips the doc-drift check. A Node test asserting a printed path must build it with `path.join`: the Windows job prints `nope\sprints`.
- Numbers stated in an issue drive behaviour: a line budget ("≤ 15 shipped lines") makes a subagent write 150-column one-liners, and cross-family reviewers grade against the literal acceptance numbers. State readability rules instead, and when "cut, don't refactor" beats an estimate, amend the acceptance on the issue and record the override on the PR rather than trimming to hit the number.
