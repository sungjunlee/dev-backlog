# Project Context

## Architecture Decisions

- Approved `spec/*` can describe behavior that is not yet shipped. #502 (one approval surface: checklist-only triage anchors) is still pending; until it lands, execute the current `backlog-triage` skill and `triage-apply` runtime, which still parse duplicated anchors.
- Plan refs are `#N` and nothing else. The one parser is `parseIssueRef` / `parsePlanCheckbox` in `scripts/lib.js`.
- Active tracks partition by scope through the ONE `scopesOverlap()` in `scripts/lib.js` — never re-implement it. `component:` equality or explicit `scope:` directory prefixes (`dir`, `dir/`, `dir/*`, `dir/**`) decide; disjoint tracks coexist as a portfolio and overlap fails loud; a component-vs-scope pair or an unsupported scope entry is "cannot prove disjoint" (warn), never "disjoint". Single-track text output is the compatibility surface (the G4 anchor in the smoke test); never snapshot `--json`, which is schema-versioned instead.
- Scripts own exactly four surfaces: the sprint-file contract, fail-loud shared-state guards (track overlap, unmoored `[~]`, `status: completed`), the `sprint-state` JSON recovery rail, and the `triage-apply` human gate. The keep test for any surface is (1) guards shared or irreversible state, (2) a deterministic check the model cannot cheaply redo, (3) a wire contract another tool consumes; failing all three means delete, not rewrite, and a reviewer defending a deleted doc must show the consumer reading it. A surface that stays keeps its CLI contract; interfaces change only when an issue explicitly changes them. Completed sprint files are disposable and may be deleted at any time: the record of what was done and how is the Issue, the epic, and the PR, and `_context.md` is the only thing kept after a close.

## Conventions

- `sprint-init.js` creates missing execution directories and refuses a symlinked or irregular `.dev-backlog/` or `sprints/` before any write. `setup-dev-backlog.js --migrate-legacy` is only the explicitly authorized, bounded legacy-layout migration; routine commands preserve existing sprint, context, and leftover `backlog/` bytes.
- Commit the active sprint file to main when opening it; a sprint that is untracked or only on a working branch is invisible to delegate worktrees branched from main, which may then seed a duplicate active sprint.
- `sprint-state.js --mode next|status` and `backlog-doctor.js` are the machine path — extend them instead of adding a second markdown parser. With relay deprecated the JSON has no external consumer; it stays as the fresh-session recovery rail; `--format text` is the readable view.
- SKILL.md is goal / rail / Done-when per mode: state a rule once, name the script that enforces it, keep hard constraints only for shared or irreversible state. Re-add prose only after a conformance run shows a repeated mistake, never for an anticipated risk. Eval prompts live in `tests/evals/`, never in SKILL.md — an in-file prompt section is a self-contaminating answer key.
- No `skills/` file may carry an unconditional required-read of a cross-repo `../spec-charter/references/` path; it dangles for adopters without craftkit and the smoke test enforces it.
- Every change lands via a PR reviewed by a model family other than the one that wrote it, iterating until LGTM; the cumulative diff gets one cross-family read at batch boundaries, which is cheaper than per-PR review and catches the contradictions repetition hides. Fresh-session conformance runs before each release tag and whenever a SKILL.md rail changes (before/after pair); recipe and retention live in `docs/conformance/README.md`; `codex exec` outside a git repo needs `--skip-git-repo-check`, takes the prompt on stdin with `-`, writes the final answer via `-o`, and reports token counts on stderr. A repeated PARTIAL earns either one clause in SKILL.md or an eval-side Expected relaxation, never both.
- The `backlog-triage` report is written by the session, not by scripts, and is GitHub-only; it reads issues via `gh` and fetches comment history or merged closing PRs only when a judgment needs them, never as a snapshot-enrichment pass. Before deleting any other judgment script, repeat the shape that retired the last ones: fixture, A render, B session report, checker over close set / protection / exclusions / anchors.

## Known Gotchas

- `gh issue create` does not support `--json`; a `create --json … || create -b "fallback"` chain fails the first call at flag parsing and posts the fallback placeholder as the real issue body. Capture the URL from stdout instead.
- Triage relationship edges are advisory: a merged-PR-link mention is evidence, not a close, which still needs an Obsolete Candidate plus an accepted apply checkbox. Never propose closing an issue referenced in the active sprint's Plan or Running Context, however stale it looks.
- In-flight Plan pointer grammar (parsed by `sprint-state.js`): `→ PR #N (state)` at end of line, or `[branch:name]`. Any other shape reads as unmoored and fails the live smoke assertion.
- When a flag is deleted, reject it explicitly rather than ignore it — a silently ignored `--dry-run` turns a preview into a real write. The rejection test is a guard on irreversible state, not a rewrite of the retired surface.
- Two parsers of one file drift: route sprint-state and doctor through the shared Node track reader; malformed active Plans must fail with source file and line instead of yielding partial recovery.
- Never chain `gh pr merge` after a grep-filtered test run — capture the full `node --test` status first. A backtick inside a JS template literal reached main for one commit this way.
- Measure suite totals with one stated glob (`tests/*.test.js tests/*/*.test.js`) and keep it across records; quote no script line counts here, since they go stale every wave and the repo-only helpers under `tests/tools/` sit outside the shipped bundle, so naming them by filename trips the doc-drift check. A Node test asserting a printed path must build it with `path.join`: the Windows job prints `nope\sprints`.
- Numbers stated in an issue drive behaviour: a line budget ("≤ 15 shipped lines") makes a subagent write 150-column one-liners, and cross-family reviewers grade against the literal acceptance numbers. State readability rules instead, and when "cut, don't refactor" beats an estimate, amend the acceptance on the issue and record the override on the PR rather than trimming to hit the number.
